Symptom: 3 of 4 Windows machines in OU=Finance (3rd Floor), confirmed hostname DESKTOP-FB031, failed to process Group Policy at startup between 07:40-07:44, logging repeated GroupPolicy errors (Event 1058 SYSVOL access failure, Event 1030 cannot query GPO list, Event 1129 no DC connectivity) alongside a Netlogon secure-channel failure (Event 5719). No service crash was observed; the machines otherwise started normally.

Cause: DHCP assigned the affected machines a decommissioned DNS server (10.10.3.250 per DESKTOP-FB031's DHCP Client Event 50036; 172.16.5.5 per server-side logs for FB055-FB057) instead of the current DNS server (10.10.0.10), because the DHCP scope for the affected Floor 3 subnet(s) was not updated when the old DNS servers were decommissioned overnight at 02:00 during a migration wave. Without a resolvable DNS server, the machines could not reach FINBRIDGE-DC01.finbridge.local, breaking Netlogon secure-channel establishment and Group Policy SYSVOL access.

Scope: OU=Finance, Floor 3; 3 of 4 machines affected, with only DESKTOP-FB031 individually confirmed in workstation-level evidence (the other two affected machines are not individually identified). DESKTOP-FB029 in the same OU was unaffected, having been manually pre-configured with the correct DNS server before the migration; server-side DHCP logs show the same affected/unaffected pattern for FB055-FB057 vs. FB058, though it is not confirmed whether these are the same machines as FB031/FB029.

Workaround: Manually set the correct DNS server (10.10.0.10) on the affected machine as a temporary override, then run `gpupdate /force` and confirm a GroupPolicy Event 1500 (success) is logged, mirroring the working configuration already seen on DESKTOP-FB029 and FB058. This is a recommended next action per the RCA - no evidence was provided confirming it has been applied to the affected machines yet.

Permanent fix: Correct the DHCP scope option(s) for the affected Floor 3 subnet(s) to reference 10.10.0.10 and remove references to the decommissioned DNS servers (10.10.3.250, 172.16.5.5). Force a DHCP lease renewal (or reboot) on affected machines so they pick up the corrected DNS server without waiting for natural lease expiry.

How to spot it: Look for Netlogon Event 5719 (secure channel failure, DNS query for the DC FQDN unanswered), DNS Client Event 1014 (name resolution timeout, no DNS server responded), and GroupPolicy Events 1058 (SYSVOL access failure, error 0x3), 1030 (cannot query GPO list, error 0x546), and 1129 (no DC connectivity). Confirm the underlying cause via DHCP Client Event 50036 showing a decommissioned DNS server assigned, and confirm recovery via a later Event 50036 showing 10.10.0.10 followed by GroupPolicy Event 1500.
