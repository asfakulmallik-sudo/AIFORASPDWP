Symptom: 3 of 4 Windows machines in OU=Finance (3rd Floor), confirmed hostname DESKTOP-FB031, fail to process Group Policy during startup, logging repeated GroupPolicy errors (Event 1058 SYSVOL access failure, Event 1030 cannot query GPO list, Event 1129 no DC connectivity) alongside a Netlogon secure-channel failure (Event 5719). No service crash is observed; the machines otherwise start normally.

Cause: DHCP hands the affected machines a decommissioned DNS server address (10.10.3.250 in this evidence; also seen as 172.16.5.5 for a related set of machines in server-side DHCP logs) instead of the current DNS server (10.10.0.10). This happens because the DHCP scope for the affected subnet was not updated when the old DNS server was decommissioned overnight (02:00) during a migration wave. Without a working DNS server, the machine cannot resolve the domain controller's FQDN, so Netlogon and Group Policy both fail.

Scope: Floor 3, OU=Finance. 3 of 4 machines affected; DESKTOP-FB029 in the same OU was unaffected because it had been manually pre-configured with the correct DNS server (10.10.0.10) before the migration wave. Server-side DHCP logs show the same pattern for FB055-FB057 (affected) vs. FB058 (unaffected, manually set) - not yet confirmed whether these are the same machines as FB031/FB029 under different naming.

Workaround: Manually set the correct DNS server (10.10.0.10) on the affected machine as a temporary override, then run `gpupdate /force` and confirm a GroupPolicy Event 1500 (success) is logged - this mirrors the working configuration already seen on DESKTOP-FB029 and FB058.

Permanent fix: Correct the DHCP scope option(s) for the affected subnet(s) to reference 10.10.0.10 and remove references to the decommissioned DNS server(s). Force a DHCP lease renewal (or reboot) on affected machines so they pick up the corrected DNS server without waiting for natural lease expiry.

How to spot it: Look for Netlogon Event 5719 (secure channel failure, DNS query for the DC FQDN returned no response), DNS Client Event 1014 (name resolution timeout, no DNS server responded), GroupPolicy Events 1058 (SYSVOL access failure, often error 0x3), 1030 (cannot query GPO list), and 1129 (no DC connectivity). Confirm the underlying cause via DHCP Client Event 50036 and check whether the DNS server listed matches a known-decommissioned address. Confirm recovery via a later Event 50036 showing the correct DNS server followed by GroupPolicy Event 1500.
